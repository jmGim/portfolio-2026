01 사용자 공간이 아는 장치 계약

/dev/ledkey는 사용자 공간 입장에서 “1바이트를 읽으면 눌린 KEY 번호, 1바이트를 쓰면 LED 8비트 패턴”이라는 계약을 가진 문자 장치입니다. GUI는 GPIO 핀 번호나 레지스터를 알 필요가 없습니다.

02 QSocketNotifier가 해주는 일

QSocketNotifier는 소켓뿐 아니라 임의의 파일 디스크립터를 이벤트 루프의 감시 대상(내부적으로 poll/select 계열)에 올립니다. fd가 읽기 가능해지면 activated 신호가 발생하고, slot에서 1바이트를 읽어 updateKeyDataSig로 UI에 전달합니다.

  1. open — QFile::handle()로 fd를 얻습니다.
  2. 감시 등록 — 이벤트 루프가 fd의 읽기 준비를 기다립니다. 스레드 대기 없이 GUI가 계속 반응합니다.
  3. read — 준비 알림이 오면 1바이트 read, 값이 양수일 때만 signal을 발생시킵니다.
  4. UI 반영 — KEY 번호를 비트 XOR로 토글해 체크박스·LCD를 갱신합니다.

핵심

이벤트 루프는 “fd가 준비됐다”는 커널의 판단을 전달할 뿐입니다. 그 판단은 드라이버의 .poll 구현에 달려 있습니다.

04 개선 설계 (제안 · 미적용)

상태 표기

아래 코드는 리뷰에서 도출한 개선안입니다. 실제 보드에서 시험하고 커밋하기 전까지 “적용 완료”로 쓰지 않습니다.

open 실패 중단 + 범위 검사 + write 결과 확인C++
bool LedKeyDev::openDevice()
{
    pQFile = new QFile(DEVFILENAME, this);          // 부모 소유로 수명 관리
    if (!pQFile->open(QFile::ReadWrite | QFile::Unbuffered)) {
        emit deviceError(pQFile->errorString());
        return false;                                // notifier 생성 중단
    }
    pQSocketNotifier = new QSocketNotifier(pQFile->handle(),
                                           QSocketNotifier::Read, this);
    connect(pQSocketNotifier, &QSocketNotifier::activated,
            this, &LedKeyDev::readKeyData);        // 함수 포인터 방식
    return true;
}

void LedKeyDev::readKeyData()
{
    char keyNo = 0;
    if (pQFile->read(&keyNo, 1) != 1) return;
    if (keyNo < 1 || keyNo > 8) return;             // 유효 범위 1~8
    emit updateKeyDataSig(int(keyNo));
}

void LedKeyDev::writeLedData(int ledVal)
{
    if (ledVal < 0 || ledVal > 255) return;
    const char v = static_cast<char>(ledVal);
    if (pQFile->write(&v, 1) != 1)
        emit deviceError("LED write failed");
}

함수 포인터 방식의 connect는 컴파일 시점에 시그널 서명을 검사합니다. Qt 5/6 양쪽에서 같은 코드를 쓰려면 QSocketNotifier::activated 오버로드 차이를 실제 빌드로 확인해야 합니다.

05 포트폴리오에서 주장할 수 있는 것

말할 수 있는 것

Linux 디바이스 파일 계약을 이해하고, fd 읽기 준비 이벤트를 Qt signal/slot으로 연결해 LED/KEY를 GUI에 통합했다.

별도 증빙이 필요한 것

커널 모듈 소스, file_operations·GPIO 요청·IRQ·.poll, 디바이스 트리, 모듈 로드 로그. 이 저장소에는 없으므로 “드라이버를 직접 개발했다”고 쓰지 않습니다.

BSP·드라이버 직무에 지원할 때는 이 글의 사용자 공간 계약 설명에 별도 드라이버 저장소와 insmod/dmesg 시험 결과를 함께 붙여야 설득력이 생깁니다.
