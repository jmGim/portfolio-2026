01 프로젝트 개요와 개발 범위

MPU6050의 가속도·자이로와 HMC5883L의 지자기 데이터를 융합해 Roll/Pitch/Yaw를 추정하고, 외부 기울기의 반대 방향으로 SG90 서보를 구동하여 기체의 수평을 유지하는 시스템을 구현했습니다.

차량 전장과 방산 제어기에서 중요한 실시간성과 고장 격리를 고려해, 하드웨어 접근부터 제어 명령까지 단일 루프에 넣지 않고 계층과 Task로 책임을 분리했습니다.

MPU6050 ── EXTI/Semaphore ─┐
                             ├─ I2C1 Mutex ─ Driver
HMC5883L ── 66ms Polling ───┘                 │
                                              ▼
                               Sensor Fusion Service
                         Roll / Pitch / Tilt-compensated Yaw
                                              │
                                              ▼
                                  Gimbal Control AP
                            Limit → LPF 보간 → PWM → SG90 ×3

02 Layered Architecture와 실시간 Task 설계

Driver → Service → Application

  • Driver — I2C, UART, PWM, EXTI와 센서 레지스터 접근 캡슐화
  • Service — Raw 센서 보정, 자세 추정과 최신 상태 제공
  • Application — 6개 Task의 실행 주기, 제어 모드, CLI와 Fault 상태 관리

MPU6050: Event-Driven

50Hz 샘플이 준비되면 PA4 EXTI가 발생합니다. ISR에서는 연산이나 I2C 통신을 수행하지 않고 Semaphore만 release한 뒤 즉시 반환합니다. 실제 읽기와 자세 계산은 깨어난 gyroSystemTask가 수행합니다.

Event-Driven IMU TaskC
void gyroSystemTask(void *argument) {
    uint32_t last_calc_tick = osKernelGetTickCount();

    while (1) {
        if (imu_is_ok() && GyroReadySemHandle != NULL) {
            if (osSemaphoreAcquire(GyroReadySemHandle,
                                   osWaitForever) == osOK) {
                uint32_t now = osKernelGetTickCount();
                float dt = (now - last_calc_tick) / 1000.0f;
                last_calc_tick = now;

                if (!imu_update_math(dt)) {
                    cliPrintf("\r\n[ALARM] Sensor Disconnected!\r\n");
                    osDelay(100);
                    continue;
                }
            }
        } else {
            osDelay(10);
        }
    }
}

HMC5883L: Time-Driven + I2C1 Mutex

인터럽트 핀이 없는 지자기 센서는 약 66ms(15Hz) 주기로 읽습니다. 두 Sensor Task가 같은 I2C1을 공유하므로 HAL 호출 전후에 공용 Mutex를 적용해 컨텍스트 스위칭 중 버스 경합을 막았습니다.

설계 효과

빠른 센서는 데이터 준비 이벤트로 깨우고, 느린 센서는 정해진 주기로 읽어 응답성과 CPU 효율을 함께 확보했습니다.

03 상보 필터와 지자기 Tilt Compensation

자이로는 짧은 시간의 변화에 강하지만 적분 오차가 누적되고, 가속도계는 절대 기울기를 제공하지만 진동에 민감합니다. 자이로 96%, 가속도 4%의 상보 필터로 두 특성을 결합했습니다.

Roll 상보 필터와 Yaw Tilt 보정C
float acc_roll = atan2f((float)imu->accel_y,
                        (float)imu->accel_z) * RAD_TO_DEG;
float gyro_rate_x = (float)imu->gyro_x / GYRO_SCALE;

imu->roll = IMU_ALPHA * (imu->roll + gyro_rate_x * dt)
          + (1.0f - IMU_ALPHA) * acc_roll;

float roll_rad  = imu->roll  / RAD_TO_DEG;
float pitch_rad = imu->pitch / RAD_TO_DEG;

float mag_x_comp = mag->mag_x * cosf(pitch_rad)
                 + mag->mag_z * sinf(pitch_rad);
float mag_y_comp = mag->mag_x * sinf(roll_rad) * sinf(pitch_rad)
                 + mag->mag_y * cosf(roll_rad)
                 - mag->mag_z * sinf(roll_rad) * cosf(pitch_rad);

float abs_yaw = atan2f(-mag_y_comp, mag_x_comp) * RAD_TO_DEG;

기체가 기울면 지자기 X/Y 벡터도 함께 왜곡됩니다. 상보 필터로 구한 Roll/Pitch를 회전식에 적용해 자기장 벡터를 수평면으로 되돌린 뒤 절대 방위각을 계산했습니다. STM32F411의 Cortex-M4F FPU를 활용해 atan2f, sinf, cosf 연산을 실시간 경로에서 처리했습니다.

04 float PWM과 LPF 보간으로 서보 지터 개선

초기 구현에서는 제어 각도를 uint8_t로 전달해 CCR 값이 계단식으로 변했습니다. 작은 센서 노이즈에도 모터가 정수 단위로 반응하면서 “툭툭” 끊기는 지터가 발생했습니다.

  1. 제어 경로를 float로 전환 — 각도와 펄스 폭의 소수점 정밀도를 유지합니다.
  2. Deadband 적용 — 오차가 0.05°보다 작으면 불필요한 갱신을 억제합니다.
  3. LPF 형태의 보간 — 현재값에 (target-current) × 0.15를 더해 부드럽게 이동합니다.
  4. Software Limit — 10°~170° 범위로 제한해 기구물 충돌을 방지합니다.
Gimbal compensation controlC
float final_roll  = servoGetInitAngle(0) + (imu_r * -1.0f);
float final_pitch = servoGetInitAngle(1) + (imu_p * -1.0f);

if (final_roll < 10.0f)  final_roll = 10.0f;
if (final_roll > 170.0f) final_roll = 170.0f;

servoSetTarget(0, final_roll,  0.15f);
servoSetTarget(1, final_pitch, 0.15f);
servoSmoothUpdate();

05 Fail-Safe 트러블슈팅

Case 1. 센서 초기화 실패 → Interrupt Storm

I2C 배선 또는 센서 전원이 불안정할 때 LED와 CLI까지 멈췄습니다. 센서가 구동되지 않은 PA4 EXTI 입력이 Floating 상태가 되어 노이즈를 반복 인터럽트로 인식했고, 과도하게 높은 NVIC 우선순위가 FreeRTOS API 호출 조건과 충돌했습니다.

  • PA4에 Pull-down을 적용해 센서 미연결 상태의 입력을 결정
  • EXTI NVIC Priority를 5로 조정해 FreeRTOS API 허용 범위와 정렬
  • I2C Timeout 시 Fault flag를 세우고 제어 Task가 무한 대기하지 않도록 처리
  • imu on 재명령 시 SCL 9-clock toggle → I2C 재초기화 → Sensor init 순으로 복구

핵심 교훈

센서 초기화 실패는 단순 통신 오류가 아니라 Floating 입력과 인터럽트 우선순위를 통해 OS 전체 장애로 확산될 수 있습니다.

Case 2. Blocking UART → CLI Task Starvation

imu on 20으로 50Hz 텍스트를 출력하면 Blocking printf가 CPU를 오래 점유해 Ctrl+C 같은 사용자 명령이 처리되지 않았습니다.

  • CLI Task를 AboveNormal로 높여 비상정지와 사용자 제어권을 우선 보장
  • 사람이 읽는 Text 모드의 최소 출력 주기를 100ms로 제한
  • 고속 진단은 compact binary packet을 사용하는 mon on 경로로 분리

방어적 설계 기준

진단 출력량이 늘어나도 제어 Task와 CLI를 굶기지 않도록, 가독성 경로와 고속 데이터 경로를 분리했습니다.
